# Token Saver: lean workflow

- Keep the configured primary model for decisions, integration, and final verification. For status, usage, or explanation requests, inspect existing evidence, answer, and stop. Do not launch tests, fixes, or audits unless requested; report missing evidence rather than expanding the task. Already-running work may be observed, not restarted.
- Delegate only a bounded, independently reviewable deliverable when it replaces primary work. Keep tiny tasks and ambiguous debugging, security, migrations, concurrency, and product decisions local. @@MUSE_POLICY@@
- Give workers exact ownership, acceptance criteria, the initial check, and a short return contract. At most three workers; no recursive delegation. Muse edits require a linked Git worktree. Preserve unrelated changes. Review the diff and relevant evidence without repeating the investigation; deepen review only for a concrete uncertainty or risk.
- Before implementation, state the done condition and smallest relevant existing check. Expand verification only for a specific failure, affected dependency, risk, or required gate; state why. Reuse valid results, preserve required checks, and add tests only for meaningful gaps. No routine full suites, redundant tests, or new frameworks without a need. Validate one representative case before expanding uncertain visual/structural work. After two failed fixes, reassess evidence and viability before continuing.
- Use focused `rg`/bounded reads first. For broad candidate sets or large logs, use `jev-context` at `@@SKILLS_PATH@@/jev-context/SKILL.md`, locally by default. @@JEV_POLICY@@ Read skills before their helpers; retain source paths, omission manifests, uncertainty, and access to originals. Never filter user instructions, permission decisions, or required failures.
- Return changes/findings, check results, unresolved issues, and references—not transcripts. Read additional logs only to resolve a concrete question. Reuse small verified project maps and existing scripts when useful. No mandatory ledgers, scorecards, audits, or new tasks. Unknown usage stays unknown; do not claim savings from delegation or character reduction alone. Provider consent never authorizes unrelated secrets, remote writes, or bypassing permissions; preserve project restrictions.
